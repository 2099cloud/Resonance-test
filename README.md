# 手機圖片掃描比對

## 設定參考圖
1. 把 JPG 或 PNG 放在 index.html 旁邊，例如 target.jpg。
2. 將 scanner.js 最上方的 TARGET_URL 改成 './target.jpg'。大小寫須與檔名一致。
3. 使用細節清楚、對比明顯的圖。也可以保留空字串，先拿另一台裝置顯示內建測試圖，並用手機掃描。

## 部署
將這個資料夾內的檔案放到 GitHub 儲存庫的 main 分支根目錄。在 Settings → Pages 選 Deploy from a branch、main 和 /(root)，儲存後用手機打開 Pages 的 HTTPS 站址。也可在電腦開啟 index.html，用「選圖測試」測試內建版本。替換參考圖後，請以 HTTP 本機伺服器或部署網址測試。

## 比對流程
相機每 300 毫秒在綠框及其附近搜尋。參考圖和取樣畫面會轉成 48 × 48 的灰階網格，分別比較亮度分布及邊緣方向，再加權合成分數。相機會搜尋多種裁切位置與尺寸，以容許距離及對準誤差。畫面會顯示比對分數和門檻。連續三次超過 MATCH_THRESHOLD 才顯示相符。分數是相關性指標，沒有機率意義。選圖模式只比較一次，且會從圖片中央裁成參考圖的比例。相機畫面及選取的照片皆在瀏覽器內處理。

對準綠框、避免反光，並讓圖案維持直立。大幅旋轉、透視變形、遮擋、模糊與構圖相近的圖片可能導致誤判。可用實際展示場地的光線測試，再調整 MATCH_THRESHOLD。

## 接上後續動作
可在 scanner.js 中監聽事件，例如：

    document.addEventListener('image-match', () => {
      // 在這裡顯示解鎖內容或進入下一關。
    });

相符狀態首次成立時會發出事件。移開圖片再重新對準，可以再次觸發。選圖測試成功也會觸發同一事件。


## 更新既有部署
覆蓋 index.html 和 scanner.js。若已有自訂參考圖，請將原本的 TARGET_URL 填回新的 scanner.js。GitHub Pages 發佈完成後重新整理網頁。
